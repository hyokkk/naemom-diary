## 1. 개요

내몸일기는 본인 1명이 매일의 건강 상태를 기록하고, 캘린더와 리포트로 한눈에 확인하는 웹앱이다.

- **사용자 범위**: 본인 1인 사용. 그룹이나 공유 기능은 두지 않는다.
- **앱 형태**: 웹앱. 앱스토어에는 출시하지 않으며, 휴대폰에서는 "홈 화면에 추가"로 앱처럼 쓴다.
- **배포 구성**: Supabase(DB/인증/사진 저장) + Netlify(호스팅). 무료 플랜 범위에서 운영한다.
- **소스 관리**: dayshare와 같은 폴더 구조로 GitHub 비공개 저장소에서 관리한다.

## 2. 화면 구성

하단 탭 7개와 머리글의 설정 버튼(톱니바퀴)으로 구성한다.

| 화면 | 진입 | 역할 |
|---|---|---|
| 오늘 기록 | 하단 탭 | 하루치 기록 입력, 날짜 이동, 영양제/정기 약 체크, 일회성 약 기입, 다른 날 기록 복사 (2.2) |
| 캘린더 | 하단 탭 | 월 단위 확인, 항목 필터, 날짜를 누르면 그날의 조회 모드 |
| 조회 모드 | 캘린더/모아보기/치료 일지의 날짜 | 하루 기록을 한 줄씩 요약해서 보기, "기록 수정"으로 편집 화면 이동 |
| 몸 상태 모아보기 | 캘린더 아래 단계 범례 | 선택한 단계로 기록한 날을 모아 보기 |
| 리포트 | 하단 탭 | 주간/월간/연간 집계 |
| 약/영양제 | 하단 탭 | 정기 복용 약과 영양제의 등록/수정, 메모·차도 |
| 약 기록 | 하단 탭 | 차도를 적은 날을 약 이름별로 모아 보기 (4.2) |
| 치료 일지 | 하단 탭, 오늘 기록의 병원 치료 카드 | 병원 치료 일지 작성/조회, 다음 예약 확인 |
| 일기 | 하단 탭 | 기록/캘린더와 상관없이 자유롭게 쓰는 글 (2.3) |
| 항목 설정 | 머리글 설정 버튼 | 항목 추가/숨김/순서/선택지 편집, 주요 증상 편집, 캘린더 항목, 로그아웃 |

오늘 기록 화면은 과거 날짜로 이동할 수 있어서, 빠뜨린 날을 나중에 채우거나 지난 기록을 고칠 수 있다. 오늘 이후 날짜로는 이동하지 않는다.

### 2.1 조회 모드

캘린더에서 날짜를 누르면 편집 화면 대신 조회 모드가 열린다. 편집 화면은 카드가 길게 이어져 스크롤이 깊기 때문에, 조회 모드는 항목마다 "이름 | 값" 한 줄로 압축한다.

- 기록한 항목만 줄로 보여 주고, 기록하지 않은 항목은 맨 아래 "기록 안 함: …"에 이름만 모은다.
- 몸 상태는 단계 색 원과 라벨, 그 아래 체크한 증상을 보여 준다. 식사는 끼니별 한 줄(메뉴, 증상)과 작은 사진을 보여 준다.
- 영양제/정기 약은 ✓/✗와 차도, 일회성 약은 "증상 → 차도", 병원 치료는 병원과 치료 내용, 첨부한 사진 장수를 보여 준다.
- 좌우 화살표로 날짜를 넘기고, "기록 수정"을 누르면 그 날짜의 편집 화면으로, "‹ 캘린더"를 누르면 캘린더로 돌아간다.
- 몸 상태 모아보기, 치료 일지의 "그날 기록 보기", 약 기록 모음의 각 줄도 조회 모드로 연결한다.

### 2.2 기록 복사

매일 비슷하게 먹는 약이나 식사를 빠르게 채우기 위한 기능이다. 오늘 기록 화면의 날짜 아래 "다른 날 기록 복사해 오기"를 누르면 복사 칸이 열린다.

- 가져올 날짜는 지금 보고 있는 날짜보다 앞에서 가장 최근에 기록한 날로 시작하며, 바꿀 수 있다. 고른 날의 기록을 한 줄로 요약해 보여 준다.
- 가져올 범위를 체크로 고른다 (기본은 모두): 몸 상태/주요 증상, 그 밖의 항목(체중, 운동/요가/간식 메모, 배변 등), 식사(메뉴, 증상), 영양제/정기 약 복용 체크, 일회성 약(이름, 증상).
- **이미 적은 칸은 덮어쓰지 않고, 비어 있는 칸만 채운다.** 주요 증상은 체크하지 않은 증상만 더한다. 일회성 약은 띄어쓰기를 뺀 이름이 같은 약이 이미 있으면 건너뛴다.
- 사진, 약 차도, 기타 메모(텍스트 항목), 치료 일지는 그날그날 다른 내용이라 가져오지 않는다.
- 영양제와 정기 약은 복사해 오는 날짜에 복용 기간인 약만 체크한다. 숨긴 항목과 숨긴 증상은 가져오지 않는다.
- 끝나면 채운 칸 수를 알려 주고, 채울 칸이 없으면 그렇다고 알려 준다.

### 2.3 일기

- 기록 항목이나 캘린더와 연결하지 않는 자유로운 글이다. 하루에 여러 편을 쓸 수 있다.
- "새 일기 쓰기"로 날짜(오늘로 시작, 오늘 이후는 불가), 제목(선택), 본문을 적는다.
- 목록은 최근 날짜부터 보여 준다. 본문은 3줄까지만 보이고, 누르면 전체를 펼친다. "수정"에서 날짜/제목/본문을 고치거나 삭제한다 (삭제는 한 번 더 눌러야 실행).

## 3. 기록 항목과 유형

### 3.1 유형 정의

모든 항목은 6가지 유형 중 하나이며, 유형에 따라 입력/캘린더 표시/리포트 집계 방식이 정해진다.

| 유형 | 입력 | 캘린더 표시 | 주간/월간 리포트 | 연간 리포트 |
|---|---|---|---|---|
| 단계형 | 순서 있는 선택지 중 하나 | 날짜 옆 단계 색 원 | 평균, 일별 추이 | 연평균, 월평균 추이 |
| 선택형 | 있음/없음 → 있음이면 선택지 | 있음: 항목 색으로 채운 표시 + 선택지 이름. 없음: 옅은 "이름 없음" 표시 | 있음 일수, 선택지별 빈도 | 월별 일수, 선택지별 빈도 |
| 숫자 | 숫자 + 단위 | 값 | 처음/마지막 값, 변화량, 일별 추이 | 월평균 추이, 연간 변화량 |
| 예/아니오 | 예/아니오 (+ 내용 칸을 켠 항목은 "예"일 때 내용 입력) | "예"인 날만 항목 색으로 채운 표시, 내용이 있으면 함께 표시 | 일수, 달성률, 자주 적은 내용 | 월별 일수, 달성률, 자주 적은 내용 |
| 식사 | 아침/점심/저녁별 메뉴 + 증상 + 사진 | 기록한 끼니 수 | 끼니별 기록률 | 끼니별 기록률 |
| 텍스트 | 자유 입력 | "메모" 표시 | 집계 없음 | 집계 없음 |

예/아니오와 선택형은 같은 버튼을 다시 누르면 기록이 지워진다. "아니오"와 "기록 안 함"을 구분하기 위해서다. 달성률은 기록한 날을 분모로 계산한다.

식사는 끼니마다 "메뉴"와 "증상" 칸을 한 줄에 두고, 오른쪽에 사진 버튼을 둔다. 증상 칸은 그 끼니를 먹고 난 뒤의 상태(예: 더부룩함)를 적는 곳이며, 메뉴 없이 증상만 적어도 된다. 메뉴/증상/사진을 모두 비우면 그 끼니 기록을 지운다.

예/아니오 항목에 내용 칸을 켜 두면, "예"를 골랐을 때 버튼 오른쪽에 내용 입력칸이 나타난다 (예: 간식 → "초코파이"). 내용은 비워 둬도 되며, "아니오"로 바꾸면 적어 둔 내용도 지운다. 내용 칸을 끄면 입력칸만 숨기고, 이미 적어 둔 내용은 남긴다.

### 3.3 몸 상태 주요 증상

몸 상태를 기록할 때 단계와 함께 주요 증상을 체크한다. 단계 없이 증상만 기록하는 것도 가능하다.

| 증상 | 기본 선택지 |
|---|---|
| 복부 팽만/가스 | 약함/보통/심함 |
| 속쓰림 | 약함/보통/심함 |
| 명치뭉침 | 약함/보통/심함 |
| 위 쥐어짬 | 약함/보통/심함 |

- 증상 이름을 누르면 체크되고, 그 옆에 선택지가 나타난다. 선택지는 고르지 않아도 되며, 이 경우 "정도 미기록"으로 집계한다.
- 같은 선택지를 다시 누르면 선택이 풀리고, 증상 이름을 다시 누르면 체크가 풀린다.
- 항목 설정 화면의 단계형 항목에 있는 "주요 증상 편집"에서 증상 목록과 증상별 선택지를 고친다.
  - **증상 추가**: 이름을 적고 "증상 추가". 새 증상은 약함/보통/심함 선택지로 시작한다.
  - **이름 수정/순서 변경**: 이름 칸에서 바로 고치고 ↑↓로 순서를 바꾼다. 이름을 바꾸면 지난 기록에도 바뀐 이름이 보인다.
  - **삭제**: 한 번 더 눌러야 실행된다. 한 번도 기록하지 않은 증상은 완전히 지운다. 기록이 있는 증상은 숨김으로 처리해 기록 화면에서만 빼고, 지난 기록과 리포트에는 남긴다. 숨긴 증상은 "다시 표시"로 되살린다.
  - **선택지**: 증상마다 "선택지 편집 · 약함/보통/심함" 한 줄로 접어 두고, 누르면 추가/이름 변경/순서 변경/숨김을 할 수 있다. 숨김과 이름 변경 규칙은 일반 선택지와 같다 (3.4).
- 증상은 단계형 항목이면 어느 항목에나 붙일 수 있다. 처음 가입하면 몸 상태에 기본 증상 4가지를 만든다. 증상을 모두 지워도 기본 증상을 다시 만들지 않는다 (설정 행이 있으면 다시 만들지 않음).

### 3.4 항목과 선택지 편집 규칙

- 항목 설정 화면에서 항목을 추가하고, 이름과 순서를 바꾸고, 숨길 수 있다.
- 예/아니오 항목은 설정 화면에서 "내용 칸 켜기/끄기"로 내용 칸 사용 여부를 정한다. 기본 항목 중 운동/요가/간식은 켜진 상태, 새로 추가한 예/아니오 항목은 꺼진 상태로 시작한다. 내용 칸의 안내 문구는 항목에 맞춘다 (운동: "어떤 운동을 했나요? (예: 걷기 30분)", 간식: "어떤 간식이었나요?").
- 새 항목은 유형을 고르고, 숫자형은 단위를, 단계형/선택형은 선택지(2개 이상)를 입력한다.
- **항목 삭제는 숨김으로 처리한다.** 기록 화면과 캘린더 필터에서 빠지고, 지난 기록과 리포트에는 남는다. 숨긴 항목은 다시 표시할 수 있다.
- 단계형/선택형의 선택지는 추가/이름 변경/순서 변경/숨김이 가능하다.
- 기록은 선택지의 고유 ID로 저장하므로, 선택지 이름을 바꾸면 지난 기록에도 바뀐 이름이 표시된다.
- 단계형의 단계 값은 선택지 목록의 위에서부터 1, 2, 3…으로 계산한다. 단계 수를 바꾸면 이전 기록과 평균을 같은 기준으로 비교하기 어렵다는 안내를 설정 화면에 표시한다.
- 단계형 항목은 "높을수록 나쁨/좋음" 방향을 가진다. 방향에 따라 캘린더 색이 바뀐다 (나쁜 쪽이 빨강). 몸 상태는 높을수록 나쁨, 새로 추가한 단계형은 높을수록 좋음으로 시작하며 설정 화면에서 바꿀 수 있다.
- v1.3 이전에 만든 몸 상태는 `migration_v1.4.sql`로 선택지 순서를 뒤집는다. 기록은 선택지 ID로 저장되어 있어서, "매우 나쁨"으로 기록한 날은 라벨이 그대로이고 단계 숫자만 1에서 5로 바뀐다.

## 4. 약/영양제와 병원 치료

### 4.1 약/영양제

| 구분 | 등록 위치 | 등록 정보 | 날짜별 처리 | 캘린더 표시 |
|---|---|---|---|---|
| 정기 복용 약 | 약/영양제 탭 | 이름, 시작일, 종료일(선택), 메모·차도 | 하루 1회 복용 체크 + 차도 | 복용 현황 (예: 1/1), 일부만 복용하면 세로선, 모두 복용하면 채운 표시 |
| 영양제 | 약/영양제 탭 | 이름, 시작일, 종료일(선택), 메모 | 하루 1회 복용 체크 | 복용 현황 (예: 2/3), 모두 복용하면 채운 표시 |
| 일회성 복용 약 | 오늘 기록 화면 | 약 이름, 증상, 차도 | 기입 자체가 기록 | 약 이름 |

- 등록 칸은 평소에 접어 두고 "+ 새 정기 복용 약 등록" / "+ 새 영양제 등록" 버튼만 보여 준다. 누르면 그 칸만 열리고, 등록하거나 "닫기"를 누르면 다시 접힌다.
- 종료일을 비우면 계속 복용 중으로 본다.
- 등록한 약/영양제는 "수정"을 눌러 이름, 시작일, 종료일을 고친다. 수정 안에 "오늘로 복용 종료"와 "삭제" 버튼이 있다.
- 메모 칸(정기 약은 "메모 · 차도")은 두 줄 높이로 항상 펼쳐 두어, 수정 버튼 없이 바로 적고 고친다.
- 목록은 약과 영양제 모두 복용 시작일이 최근인 순서로 정렬한다.
- 정기 복용 약 중 복용이 끝난 약은 기본으로 숨기고, "복용 종료된 약 N개 보기"를 누르면 작은 글씨 목록(이름, 기간, 메모)으로 펼친다. 펼친 목록에서도 "수정"으로 다시 편집할 수 있다.
- 정기 복용 약은 복용 기간인 날의 기록 화면에서 복용 여부를 체크하고, 체크하면 차도 입력칸이 나타난다. 차도는 나중에 적어도 된다.
- 상태는 시작 전이면 "예정", 종료일이 지났으면 "종료", 그 밖에는 "복용 중"으로 표시한다.
- 영양제는 복용 기간인 날의 기록 화면에 체크리스트로 나타난다.
- 일회성 복용 약은 하루에 여러 건을 기입할 수 있다. 등록한 약의 이름, 증상, 차도는 칸에서 바로 고친다. 이름은 비울 수 없으며 (비우면 원래 이름으로 돌아감), 지우려면 "삭제"를 누른다.
- 차도는 약을 먹은 직후에는 알기 어려우므로, 추가한 약마다 차도 입력칸을 남겨 두고 나중에 채울 수 있게 한다.

### 4.2 약 기록 모음

약/영양제 탭은 약을 등록하고 관리하는 곳이고, "약 기록" 탭은 그 약이 실제로 들었는지 돌아보는 곳이다.

- 차도를 적은 기록만 모은다. 정기 복용 약은 그날 복용 체크와 함께 적은 차도, 일회성 약은 증상과 차도를 대상으로 한다. 차도를 적지 않은 날은 빠진다.
- 약 이름별로 카드를 하나씩 두고, 카드 안에서는 최근 날짜부터 "날짜 | 증상 → 차도" 한 줄씩 보여 준다. 카드는 가장 최근 기록이 있는 약부터 나열한다.
- 일회성 약은 이름이 같은 기록을 한 카드로 묶는다. 띄어쓰기와 영문 대소문자만 다른 이름은 같은 약으로 본다 (띄어쓰기는 모두 빼고 비교한다. 예: "케이캡정25mg" = "케이캡정 25mg"). 정기 약과 일회성 약의 이름이 같으면 같은 카드에 넣고, 줄마다 "정기/일회성"을 붙인다.
- 카드 제목 줄에 종류(정기/일회성), 기록 건수, 최근 날짜를 표시한다. 같은 이름의 정기 약에 메모가 있으면 제목 아래에 작은 글씨로 보여 준다.
- 기록이 3건보다 많으면 3건만 보여 주고 "N건 더 보기"로 펼친다.
- 줄을 누르면 그날의 조회 모드가 열린다.

### 4.3 병원 치료와 치료 일지

- 병원 치료 기록은 하루에 1건이다. 기록이 있으면 그날을 "치료 받은 날"로 본다.
- 오늘 기록 화면 맨 아래의 "병원 치료" 카드에서 "치료 받은 날"을 누르면 기록이 생기고, 치료 일지로 이동하는 버튼이 나타난다.
- 일지 내용이 비어 있으면 같은 버튼으로 바로 해제한다. 내용이 있으면 한 번 더 눌러야 해제되며, 이때 일지도 함께 삭제된다.
- 치료 일지 탭에서는 날짜를 골라 새 일지를 쓰고, 지난 일지를 최근 순으로 본다. 오늘 이후 날짜에는 일지를 쓰지 않으며, 예약은 "다음 예약일"에 적는다.
- **일지 복사**: 같은 병원에 다시 다녀온 날을 빠르게 쓰기 위한 기능이다. "가장 최근 일지 복사해서 쓰기"는 고른 날짜에 가장 최근 일지를, 일지 편집 화면의 "복사"는 그 일지를 다른 날짜에 복사한다. 병원, 치료 내용, 소견은 그대로 옮기고 다음 예약일과 사진은 옮기지 않는다. 이미 일지가 있는 날짜나 오늘 이후 날짜로는 복사하지 않는다.

| 일지 칸 | 내용 |
|---|---|
| 날짜 | 치료 받은 날. 바꾸면 일지가 그 날짜로 옮겨진다 (이미 일지가 있는 날로는 옮기지 않음) |
| 병원 / 진료과 | 예: 우리내과 소화기내과 |
| 치료 내용 | 검사, 시술, 상담 내용 |
| 의사 소견 / 처방 | 진단, 처방약, 생활 지침 |
| 다음 예약일 | 치료 일지 탭 위쪽에 가장 가까운 예약일과 남은 일수(D-7 등)를 표시 |
| 처방전/소견서 등 | 사진 여러 장 첨부. 썸네일을 누르면 크게 보고, × 로 한 장씩 지운다. 일지 목록에는 "처방전/소견서 사진 N장"으로 표시 |

- 일지 날짜를 옮기면 사진도 함께 옮겨지고, 일지를 지우면 사진(저장소 파일 포함)도 함께 지워진다.

## 5. 캘린더와 필터

- 월 단위 달력이며 일요일부터 시작한다 (일~토). 오늘 이후 날짜는 비워 둔다.
- 필터는 화면에 항상 펼쳐 두고, 여러 개를 동시에 고를 수 있다.
- **캘린더 항목**: 설정 화면에서 필터 대상마다 세 가지 중 하나를 고른다.
  - 숨김: 캘린더 위쪽 목록에서 뺀다. 기록은 그대로 남는다.
  - 표시: 목록에 있고, 눌러야 켜진다.
  - 처음부터 켜기: 캘린더 탭을 열 때마다 켜진 상태로 시작한다. 기본값은 병원 치료, 몸 상태, 영양제다.
- 다른 탭에서 캘린더 탭으로 들어올 때마다 "처음부터 켜기" 상태로 돌아가며, 캘린더에서 잠깐 켜고 끈 필터는 조회 모드나 모아보기를 오가는 동안에만 유지한다. 이 설정은 DB에 저장해 기기를 바꿔도 같다.
- 필터 대상은 병원 치료, 숨기지 않은 기록 항목 전부, 주요 증상, 영양제, 정기 복용 약, 일회성 약이며, 이 중 "숨김"으로 고른 것은 빠진다.
- 필터 순서는 병원 치료, 몸 상태, 주요 증상으로 시작하고, 이후 항목 설정 순서를 따른다.
- 날짜를 누르면 그날의 조회 모드가 열린다 (2.1).

### 5.1 색 규칙

| 대상 | 표시 |
|---|---|
| 단계형 (몸 상태) | 날짜 숫자 오른쪽에 **숫자가 들어간 원**. 색은 좋은 쪽이 초록, 나쁜 쪽이 빨강이다. 몸 상태는 높을수록 나쁨이라 1단계 초록 → 3단계 노랑 → 5단계 빨강 |
| 그 밖의 항목 | 항목마다 고유 색. 필터 칩에도 같은 색 점을 붙여서 대응 관계를 보여 준다 |
| 강조(채운 표시) | 예/아니오의 "예", 선택형의 "있음", 영양제를 모두 복용한 날 |
| 옅은 "없음" 표시 | 선택형을 "없음"으로 기록한 날 (예: 배변 없음). 기록하지 않은 날은 아무것도 표시하지 않는다 |
| 옅은 표시 | 체중, 식사, 메모, 일회성 약, 영양제 일부 복용 |
| 세로선 표시 | 정기 복용 약 일부 복용 (모두 복용하면 채운 표시) |
| 병원 치료 | 치료 받은 날은 **칸 전체를 옅은 빨간색**으로 칠하고 날짜 숫자를 빨간색으로 표시하며, 날짜 옆에 **병원 아이콘**(빨간 십자)을 붙인다. 다음 예약일에는 테두리만 있는 아이콘을 붙이며, 미래 날짜에도 표시한다 |
| 주요 증상 | 그날 체크한 증상 수 (예: 증상 2), 주황색 |

단계가 5개가 아닌 단계형 항목도 1~5단계 색 범위에 맞춰 환산해 칠한다.

**칸 안의 글자**: 아이폰13(너비 390px) 기준으로 칸 하나가 약 45px이라, 항목 이름을 붙이면 "배변..."처럼 값이 잘린다. 그래서 항목 이름은 빼고 값만 보여 주며, 어떤 항목인지는 필터 칩과 같은 색으로 구분한다. PC에서는 마우스를 올리면 항목 이름까지 나온다 (title).

| 대상 | 칸 안의 글자 |
|---|---|
| 선택형 (배변) | 선택지 이름 ("정상"), 없음이면 "없음" |
| 예/아니오 | 내용을 적었으면 그 내용 ("필라테스", "초코파이"), 없으면 항목 이름 앞 두 글자 ("운동") |
| 숫자 | 값과 단위 ("61.5kg") |
| 영양제/정기 복용 약 | 복용 수/전체 ("2/3") |

메모가 길면 칸 너비에서 잘리며, 날짜를 눌러 조회 모드에서 전체를 본다.

### 5.2 단계 범례

필터에서 단계형 항목을 고르면 달력 아래에 단계별 색 범례가 나온다. 범례의 단계를 누르면 "몸 상태 모아보기"로 이동한다.

## 6. 몸 상태 모아보기

선택한 단계로 기록한 날을 모아서, 그날의 다른 기록과 함께 보여 준다. 컨디션이 나빴던 날에 공통으로 나타나는 기록을 비교하는 용도다.

- 화면 위쪽에서 1~5단계를 바꿀 수 있고, 단계마다 해당 일수를 표시한다.
- 전체 기록 기간을 대상으로 하며, 최근 날짜부터 나열한다.
- 각 날짜에 병원 치료, 체크한 주요 증상과 정도, 운동/요가/간식(적은 내용 포함)/체중/배변/영양제/일회성 약/식사/메모를 함께 표시한다.
- 날짜를 누르면 그날의 조회 모드가 열린다.
- 단계형 항목이 여러 개라면 위쪽 칩으로 항목을 바꾼다.

## 7. 리포트

주간/월간/연간을 전환하고, 이전/다음 기간으로 이동한다. 오늘 이후 날짜는 집계에서 뺀다.

| 구분 | 기간 | 그래프 단위 |
|---|---|---|
| 주간 | 월요일 ~ 일요일 (캘린더와 달리 월요일 시작 유지) | 일별 |
| 월간 | 1일 ~ 말일 | 일별 |
| 연간 | 1월 1일 ~ 12월 31일 | **월별** (1년을 일별로 그리면 점이 너무 촘촘해지기 때문) |

스크롤을 줄이기 위해 항목마다 카드를 두지 않고, 아래 카드로 묶는다. 막대 항목은 "이름 | 막대 | 값" 한 줄에, 필요하면 아래에 작은 글씨 한 줄을 붙인다.

| 카드 | 내용 |
|---|---|
| 단계형 (몸 상태 등) | 제목 줄에 평균/단계 수/방향/기록 일수. 추이 그래프(주간·월간은 일별, 연간은 월평균). 아래에 주요 증상 줄 (기록한 날 중 체크한 일수, 작은 글씨로 정도별 일수) |
| 숫자 (체중 등) | 제목 줄에 최근 값, 처음 대비 변화량, 기록 일수. 추이 그래프 |
| 생활 기록 | 예/아니오와 선택형 항목: "예(있음)인 날 / 기록한 날" 막대, 작은 글씨로 적은 내용이나 선택지별 일수. 식사: 기록한 끼니 / 전체 끼니, 작은 글씨로 끼니별 수 |
| 약/영양제 | 정기 약과 영양제: 복용한 날 / 복용 기간 막대. 정기 약은 최근 차도 3건. 일회성 약은 "날짜 약 · 증상 → 차도" 한 줄씩 (연간은 약 이름별 횟수) |
| 병원 치료 | 치료 받은 날 수, "날짜 병원 · 치료 내용" 한 줄씩 |

- 연간 리포트의 생활 기록과 주요 증상은 막대 자리에 1~12월 작은 월별 막대를 그린다.
- 사용자가 추가한 항목도 유형에 따라 같은 방식으로 자동 집계한다.
- 숨긴 항목은 해당 기간에 기록이 있을 때만 "(숨김)" 표시와 함께 나온다.

## 8. 로그인과 계정

- 아이디/비밀번호로 로그인한다. 처음에는 "계정 만들기"로 아이디와 비밀번호를 정한다.
- 아이디 규칙: 영문 소문자/숫자/`.`/`_`/`-`, 3~20자. 비밀번호는 6자 이상(Supabase 기본 최소 길이).
- Supabase 인증은 이메일 기반이므로, 아이디를 내부적으로 `아이디@naemom.app` 형식으로 바꿔 저장한다. 실제로 메일을 보내지 않으므로 Supabase의 이메일 확인 기능은 끈다.
- 계정을 만든 뒤에는 Supabase에서 새 가입을 막아서, 다른 사람이 주소를 알아도 계정을 만들 수 없게 한다.
- 로그인 상태는 기기에 유지되며, 설정 화면에서 로그아웃한다.

## 9. 데이터 모델

모든 테이블에 `user_id`를 두고, 행 단위 보안(RLS)으로 본인 행만 읽고 쓰게 한다.

| 테이블 | 주요 컬럼 | 설명 |
|---|---|---|
| `items` | id, user_id, name, type, unit, sort_order, is_hidden, has_note, high_is_bad | 기록 항목 정의 (has_note: 예/아니오 항목의 내용 칸 사용 여부, high_is_bad: 단계형의 방향) |
| `item_options` | id, user_id, item_id, label, sort_order, is_hidden | 단계형/선택형 선택지 |
| `daily_records` | user_id, date, item_id, value_num, value_bool, value_text, option_id | 날짜별 항목 기록 (항목당 하루 1건) |
| `symptoms` | id, user_id, item_id, name, sort_order, is_hidden | 단계형 항목(몸 상태)에 딸린 주요 증상 목록 |
| `symptom_options` | id, user_id, symptom_id, label, sort_order, is_hidden | 증상별 선택지 |
| `symptom_records` | user_id, date, symptom_id, option_id | 날짜별 증상 체크. 행이 있으면 체크, option_id가 비어 있으면 정도 미기록 |
| `meals` | user_id, date, meal_type, note, symptom, photo_path, thumb_path | 끼니별 기록 (breakfast/lunch/dinner). note는 메뉴, symptom은 먹고 난 뒤 증상 |
| `medications` | id, user_id, kind, name, start_date, end_date, note | 정기 복용 약(regular)과 영양제(supplement) |
| `supplement_logs` | user_id, date, medication_id | 영양제 복용 체크. 행이 있으면 복용 |
| `regular_med_logs` | user_id, date, medication_id, effect | 정기 약 복용 체크. 행이 있으면 복용, effect는 차도 |
| `onetime_meds` | id, user_id, date, name, symptom, effect | 일회성 복용 약 (증상, 차도) |
| `hospital_visits` | user_id, date, hospital, treatment, note, next_date | 병원 치료 일지 (하루 1건, 행이 있으면 치료 받은 날) |
| `visit_photos` | id, user_id, visit_date, photo_path, thumb_path | 치료 일지 사진. (user_id, visit_date)가 일지를 가리키며, 일지를 지우면 함께 지워진다 |
| `user_settings` | user_id, cal_defaults, cal_hidden | 사용자 설정 (사용자당 1행). cal_defaults는 캘린더를 열 때 켜 둘 필터 키, cal_hidden은 캘린더 위쪽 목록에서 뺀 필터 키 |
| `diary_entries` | id, user_id, date, title, body, created_at, updated_at | 일기 (하루에 여러 편 가능) |

항목 유형별 저장 위치는 다음과 같다.

| 유형 | value_num | value_bool | value_text | option_id |
|---|---|---|---|---|
| 단계형 | | | | 선택한 단계 |
| 선택형 | | 있음/없음 | | 있음일 때 선택지 |
| 숫자 | 값 | | | |
| 예/아니오 | | 예/아니오 | 내용 (예일 때만) | |
| 텍스트 | | | 내용 | |

캘린더에서 잠깐 바꾼 필터, 리포트 기간 같은 화면 상태는 DB가 아니라 기기의 브라우저 저장소에 둔다. 캘린더 항목 설정(처음부터 켜기/숨김)은 DB(`user_settings`)에 둔다.

## 10. 사진 저장 정책

- 사진은 Supabase Storage의 비공개 버킷 `meal-photos`에 저장한다. 식사 사진은 `사용자ID/날짜/끼니-시각.jpg`, 치료 일지 사진은 `사용자ID/visits/날짜/시각.jpg`이며, 사용자 폴더 단위로 접근 권한을 건다.
- 무료 플랜은 서버에서 이미지를 변환해 주지 않으므로, 업로드 전에 브라우저에서 압축한다. 식사 사진은 긴 변 1024px, 썸네일 160px로 줄인다. 치료 일지 사진은 처방전 글씨를 읽을 수 있도록 긴 변 1280px, 썸네일 200px로 줄인다.
- 화면에는 1시간짜리 서명 주소로 불러온다.
- 사진을 지우면 저장소의 원본과 썸네일도 함께 지운다.

| 항목 | 무료 플랜 한도 | 영향 |
|---|---|---|
| 파일 저장 용량 | 1GB | 사진 1장 약 200KB 가정 시 하루 3장 1년 약 220MB (추정치, 실제 압축 크기로 재확인 필요) |
| 데이터베이스 | 500MB | 텍스트/숫자 기록은 용량을 거의 차지하지 않음 |
| 활성 프로젝트 수 | 2개 | dayshare와 내몸일기로 무료 자리를 모두 사용 |
| 비활성 정지 | 7일 미사용 시 일시 정지 | 매일 기록하면 문제없으나, 장기간 쉬면 정지될 수 있음 |

## 11. 배포와 소스 관리

dayshare와 같은 구조를 따른다.

| 경로 | 내용 |
|---|---|
| `src/app.js` | 앱 원본 코드 |
| `template.html` | HTML 껍데기 |
| `supabase/setup.sql` | 처음 설치용 SQL (테이블, 권한, 사진 버킷) |
| `supabase/migration_v*.sql` | 이미 쓰고 있는 DB를 올리는 SQL (데이터 유지) |
| `docs/설계서.md` | 이 문서 |
| `site/` | 아이콘, 매니페스트 |
| `dist/` | 배포용 폴더 (빌드로만 생성, 저장소에 포함) |
| `test/` | 가짜 Supabase를 이용한 자동 테스트 |

- 호스팅은 Netlify에 `dist` 폴더를 끌어다 놓는 방식으로 시작한다.
- 테이블 구조가 바뀌는 수정은 Supabase SQL을 먼저 실행한 뒤 배포한다.
